# 全球领导人支持率投票系统全案设计

版本日期：2026-06-01  
定位：匿名、全球化、只投“支持 / 不支持”的领导人满意度网站  
文档用途：产品立项、UI 设计、技术开发、合规评审、商业化规划

> 重要说明：本方案不是法律意见。它的目标是把产品设计成更低风险、更透明、更合规的形态；正式上线前，仍需要按目标市场请当地律师复核隐私、广告、政治内容、数据跨境、ICP/许可等事项。

---

## 1. 核心概念

这是一个面向全球用户的匿名投票网站。用户无需注册、无需留言，只能对一个领导人点击：

- 支持
- 不支持

网站覆盖两类人物：

- 现任与近现代公共领导人：国家元首、政府首脑、政党领导人、重要国际组织领导人等。
- 历史领导人物：古代君主、革命领导人、政府首脑、军事或社会运动领袖、国际组织奠基者等。

产品不是正式民调、不是选举、不是政治竞选工具，而是一个“全球公众情绪温度计”。所有页面都要清楚标注：结果只代表本站访问者的匿名点击，不代表科学抽样民调，也不代表任何官方评价。

## 2. 可以设计进去的核心功能

### 2.1 用户侧功能

1. 全球领导人库  
   用户可以按国家 / 地区、时代、职位、在任时间、历史类别、热门程度筛选。

2. 领导人详情页  
   展示头像、姓名、国家 / 地区、主要职位、任期、简短简介、关键时间线、资料来源、投票按钮、实时结果。

3. 只允许二选一投票  
   支持 / 不支持。没有评论区，没有公开留言，没有用户主页。

4. 近期满意度与总满意度  
   每个人物展示：
   - 近 24 小时
   - 近 7 天
   - 近 30 天
   - 全站累计

5. 世界榜单  
   不能只按百分比排序，要加入最低票数门槛和置信校正，避免“2 票 100% 支持”排第一。

6. 历史时间轴  
   把历史人物按时代展示，例如古代、近代、20 世纪、冷战后、当代。

7. 全球热力图  
   只展示国家 / 地区级聚合数据，不展示城市、IP、个人轨迹。

8. 资料纠错入口  
   不开放评论，但可以有“资料纠错 / 权利请求”表单。该表单不公开展示，由后台处理。

9. 多语言  
   建议首批支持中文、英文、西班牙文、法文、阿拉伯文、印地语。界面文本短而克制，简介采用人工审核翻译。

10. 分享卡片  
   用户投票后可生成图片卡片：人物、当前支持率、时间窗口、本站免责声明。卡片不包含用户选择，避免暴露个人政治倾向。

### 2.2 管理侧功能

1. 领导人资料管理  
   新增、编辑、归档、合并重复人物、管理别名和多语言名称。

2. 简介版本管理  
   每次修改简介都保留版本、编辑人、审核人、来源链接和发布时间。

3. 智能资料草稿  
   AI 可以生成简介初稿、摘要和翻译，但必须经过人工审核后发布。

4. 合规风险扫描  
   AI 检查简介是否存在侮辱、未证实指控、带倾向性表述、煽动性措辞、版权风险。

5. 异常投票检测  
   识别短时间暴增、同来源重复点击、数据中心 IP、自动化脚本、异常国家分布。

6. 投票冻结与回滚  
   某个人物出现攻击流量时，管理员可临时冻结公开排名，保留详情页并显示“数据校验中”。

7. 内容审核工作流  
   草稿 -> 编辑审核 -> 法务 / 合规抽检 -> 发布。

8. 投诉与权利请求  
   支持隐私请求、资料纠错、版权投诉、名誉权相关通知、执法请求记录。

9. 审计日志  
   所有后台操作留痕，包括登录、修改、发布、删除、导出、权限变更。

10. 数据看板  
   展示全站访问、投票量、人物热度、异常比例、国家 / 地区分布、广告收入、会员收入。

## 3. 产品边界与红线

### 3.1 必须坚持的边界

- 不做正式民调宣称。
- 不宣称“一人一票”，因为匿名系统无法严格证明真实身份。
- 不收集真实姓名、身份证件、邮箱、手机号。
- 不开放评论区，降低违法内容、辱骂、仇恨言论和名誉侵权风险。
- 不允许付费增加票数。
- 不出售个人级投票数据。
- 不接受候选人、政党、政府机构购买“置顶支持率”。
- 不做定向政治广告。
- 不对个人进行政治画像。

### 3.2 法律风险红线

| 风险 | 设计规避方式 |
|---|---|
| 被误认为正式选举或民调 | 全站写明“非官方、非科学抽样、仅代表本站匿名点击” |
| 个人政治倾向数据泄露 | 不登录、不保存真实身份、聚合展示、短期保留风控事件 |
| 名誉侵权 / 诽谤 | 简介中只写可核验事实，不写侮辱性评价；争议内容必须有可靠来源 |
| 版权侵权 | 人物图片只用公有领域、可商用授权、授权购买或自有生成素材 |
| 广告违法 / 误导 | 原生广告、赞助栏目必须明显标注“广告 / 赞助” |
| 政治广告监管 | 不接受影响选举、候选人或政策结果的政治广告投放 |
| 未成年人隐私 | 不面向儿童，不收集儿童个人信息；必要时加入年龄提示 |
| 数据跨境 | 按主要市场配置数据区域、隐私政策、DPA、SCC 等机制 |
| 中国大陆部署 | 若服务器在中国大陆，需评估 ICP 备案、互联网新闻信息服务许可等要求 |

## 5. 高级美术 UI 设计

### 5.1 设计关键词

- 公民广场：开放、透明、可信。
- 国际档案馆：人物资料要有历史厚度。
- 数据仪表盘：投票结果清晰、可比较。
- 世界地图：全球参与感强。
- 无评论噪音：界面保持冷静，不煽动情绪。

### 5.2 视觉方向

推荐风格：`全球公共事务数据平台 + 历史档案馆 + 现代投票终端`。

不要做成娱乐八卦站，也不要做成强烈党派宣传站。视觉应当克制、精致、可信，强调数据、来源和透明度。

**高阶视觉层（2026-06 原型已实现，见仓库根目录 `index.html`）**

- 首页与 `/map` 使用 **Leaflet + Carto 暗色底图 + 国家 GeoJSON 填色**（按近 30 天支持率绿/灰/红），人物为经纬度标记，可点击弹窗投票入口。
- 视觉实现见 `assets/css/premium.css`：档案纸感浅色区 + 影院级深色地图英雄区 + 衬线标题 + 金线编辑细节 + 墨底页脚。
- 导航滚动后毛玻璃收束；正文区保持浅色档案纸质感 + 细微噪点纹理。
- 标题使用 `Instrument Serif` + 正文 `Inter` / `Noto Sans SC`，数据使用 `IBM Plex Mono` 等宽数字。
- 榜单行：头像、校正支持率、迷你趋势 sparkline、悬停浮起阴影；前三名金色序号。
- 人物页：三栏（档案侧栏 / 数据中枢 / 粘性投票面板），环形仪表盘 + Canvas 趋势图，金色时间轴刻度。

### 5.3 色彩系统

建议避免单一蓝色或单一红色政治暗示，采用多色平衡：

```css
--bg: #f7f8f3;              /* 清爽浅底，不做厚重米色 */
--surface: #ffffff;
--ink: #15171a;
--muted: #68707a;
--line: #d9ded8;

--support: #16836f;         /* 支持：冷静绿色 */
--oppose: #d94f45;          /* 不支持：克制珊瑚红 */
--neutral: #657080;
--gold: #b98b2f;            /* 历史 / 档案强调 */
--civic-blue: #2458a6;      /* 地图和链接 */
--violet: #6b4fb3;          /* 少量用于历史时间轴 */
```

使用原则：

- 支持 / 不支持只能用绿色 / 红色，不再引入复杂情绪色。
- 排行榜、地图、趋势图用中性色为主，避免“红蓝阵营感”。
- 历史人物可加入金色细线、档案纸纹理、时间轴刻度。
- 重要按钮必须有高对比度，不只靠颜色区分。

### 5.4 字体与排版

- 中文：思源黑体 / Noto Sans SC。
- 英文与多语言：Inter / Noto Sans。
- 数字：使用等宽数字特性的字体，保证百分比和票数对齐。
- 标题不要过大，除首页外保持数据产品的密度。
- 人物详情页首屏必须同时看到人物、简介摘要和投票按钮。

### 5.5 首页设计

首屏不是营销落地页，而是可用的投票入口。

布局：

- 顶部导航：Logo、探索、排行榜、历史、地图、方法论、语言切换。
- 主视觉：全屏宽度的互动地球或世界地图。
- 地图上浮动热点：今日投票增长最快的人物。
- 左侧标题区：`全球领导人支持率`
- 副文案：`匿名点击，查看世界各地对现任与历史领导人的支持 / 不支持趋势。`
- 搜索框：输入人物、国家、时代。
- 快速入口：现任领导人、历史人物、今日热榜。
- 首屏底部露出热门榜单，提示页面可继续滚动。

视觉细节：

- 地球 / 地图用 WebGL 或 Canvas，带细微动效。
- 热点不是装饰圆球，而是对应真实人物或国家的数据点。
- 首页不放大段说明文字，把“方法论”放到独立页。

### 5.6 人物详情页设计

核心区域：

- 左侧：头像、姓名、国家 / 地区、职位、任期、人物标签。
- 中部：支持率仪表盘、趋势曲线、全球热力缩略图。
- 右侧：投票面板。

投票面板：

- 两个同等大小按钮：支持、不支持。
- 按钮内使用图标 + 文案。
- 投票后按钮变为已选择状态，可显示“已记录”。
- 不出现评论框。
- 不显示“你的政治倾向”等敏感提示。

结果展示：

- 支持率：`支持 / (支持 + 不支持)`。
- 显示样本量：`本周期有效票数 128,450`。
- 显示时间窗口：`近 30 天`。
- 显示说明：`本站非科学抽样民调`。

简介区：

- 80-150 字中立摘要。
- 关键任期和头衔。
- 3-6 个关键事件时间线。
- 资料来源链接。
- 争议内容只用事实描述，不做审判式结论。

### 5.7 排行榜设计

榜单不要只追求刺激，要突出可信：

- 榜单名称明确：`近 30 天支持榜`、`近 7 天不支持榜`。
- 每行展示：头像、姓名、国家、时期、支持率、有效票数、趋势箭头。
- 排名用校正分，不直接用原始百分比。
- 低票数人物显示“数据不足”，不进入主榜。

推荐榜单：

- 全球支持榜
- 全球不支持榜
- 今日热度榜
- 历史人物支持榜
- 现任领导人支持榜
- 争议榜：支持率在 45%-55% 且票数高
- 新增人物榜

### 5.8 管理后台 UI

后台风格要像专业风控系统：

- 左侧固定导航。
- 顶部全局搜索。
- 右侧告警抽屉。
- 表格密度高，但保留足够行高。
- 所有危险操作需要二次确认。
- 审核流使用状态标签：草稿、待审核、需修改、已发布、已归档、冻结。

后台首页模块：

- 实时投票折线图
- 异常请求占比
- 热门人物
- 待审核简介
- 待处理合规请求
- 收入概览

## 6. 投票规则与结果算法

### 6.1 匿名投票的现实限制

匿名投票无法同时做到：

- 完全匿名
- 完全一人一票
- 完全防刷

所以产品应采用“隐私优先的抗滥用投票”，并公开说明：

> 我们不识别真实身份。系统会使用隐私保护的技术信号限制自动化刷票和重复投票，因此结果是匿名访问者投票趋势，不是官方选举或科学抽样民调。

### 6.2 建议规则

- 同一匿名设备 / 浏览器对同一人物在一个周期内保留最后一次选择。
- 周期建议：24 小时、7 天、30 天、全部时间。
- 可以允许用户改投，但只保留最新选择。
- 对异常流量不立即计入公开结果，进入待校验池。
- 公开结果只展示聚合数据。

### 6.3 排名校正

基础支持率：

```text
support_rate = support_votes / (support_votes + oppose_votes)
```

榜单排序建议使用 Wilson score 或贝叶斯校正，降低小样本极端值：

```text
rank_score = confidence_adjusted_support_rate
```

榜单进入条件：

- 近 30 天有效票数 >= 1000 才进入全球榜。
- 历史人物榜可以降低到 >= 300。
- 新增人物榜单独展示，不与成熟榜单混排。

### 6.4 数据展示原则

- 永远显示票数。
- 永远显示时间窗口。
- 永远显示是否包含异常过滤。
- 不展示个人级数据。
- 国家 / 地区维度低于最低样本量时隐藏。

## 7. 资料与人物库设计

### 7.1 人物收录标准

可收录：

- 国家元首
- 政府首脑
- 重要王室 / 君主
- 政党或运动领导人
- 国际组织领导人
- 历史上对国家或地区治理产生重要影响的人物

不建议收录：

- 纯娱乐明星
- 网红
- 未成年人
- 普通公务人员
- 无可靠资料来源的人物
- 仅因争议事件突然走红的人物

### 7.2 人物字段

```text
id
slug
display_name
native_name
aliases
country_or_region
position_titles
era
birth_year
death_year
term_start
term_end
is_current
is_historical
short_bio
bio_sources
portrait_url
portrait_license
risk_level
status
created_at
updated_at
```

### 7.3 简介写作规范

简介必须：

- 中立、短、事实导向。
- 写清楚职位和时期。
- 对争议使用“其政策 / 行动受到……批评”这类中性表述。
- 每条争议信息必须有来源。
- 对在世人物更加谨慎。
- 不使用侮辱性形容词。
- 不写未经证实的犯罪指控。

简介模板：

```text
{姓名} 是 {国家/地区} 的 {职位/历史身份}，主要活跃于 {时期}。
其任内 / 领导期间的主要事件包括 {事件1}、{事件2}。
支持者通常强调 {可证实贡献}，批评者则关注 {可证实争议}。
```

### 7.4 数据来源建议

- Wikidata：适合结构化字段，注意核验。
- Wikipedia：可参考但不要整段复制；如复用文本须遵守 CC BY-SA 授权。
- Wikimedia Commons：图片必须逐张检查授权、作者和署名要求。
- 官方政府 / 组织网站：适合现任人物头衔和任期。
- Britannica、Nobel、UN、World Bank 等权威资料：适合历史简介。

## 8. 智能管理系统

### 8.1 AI 能做什么

1. 生成简介初稿  
   输入人物结构化资料，输出 100 字、300 字、600 字三个版本。

2. 风险扫描  
   标记可能的：
   - 侮辱性语言
   - 未证实指控
   - 明显政治倾向
   - 仇恨或煽动性内容
   - 版权高风险文本

3. 来源一致性检查  
   对比简介中的任期、职位、出生年份、关键事件是否和来源冲突。

4. 多语言翻译  
   翻译后保留专有名词、职位、国家名称的一致性。

5. 异常投票解释  
   发现某人物票数暴涨时，给出可能原因：社媒传播、机器人、单一地区集中、数据中心流量。

6. 审核优先级排序  
   在世人物、争议人物、高流量人物优先进入人工审核。

### 8.2 AI 不能做什么

- 不能自动发布在世人物争议内容。
- 不能生成或推断用户个人政治画像。
- 不能根据用户投票给用户贴标签。
- 不能自动删除合法但负面的历史事实。
- 不能伪造来源。
- 不能把 AI 草稿当作事实来源。

### 8.3 后台角色

| 角色 | 权限 |
|---|---|
| Owner | 全部权限、财务、系统设置 |
| Admin | 管理人物、审核、风控 |
| Editor | 创建和编辑人物资料 |
| Fact Checker | 核查来源、通过简介 |
| Compliance | 处理隐私、版权、名誉请求 |
| Analyst | 查看聚合数据，不可看风控密钥 |
| Ad Manager | 管理广告位和赞助内容 |

### 8.4 审核工作流

```text
创建人物
  -> AI 生成草稿
  -> 编辑修订
  -> 来源核查
  -> 风险扫描
  -> 人工审批
  -> 发布
  -> 定期复审
```

在世或现任人物必须比历史人物更严格：

- 至少 2 个可靠来源。
- 争议内容必须可核验。
- 不使用情绪化标题。
- 法务可抽检。


投票请求示例：


后端处理：

- 检查 CSRF / Origin。
- 检查限流。
- 生成隐私保护投票键。
- 判断是否需要 CAPTCHA。
- 写入短期事件表。
- 更新聚合表。
- 返回聚合结果。

### 9.5 匿名与防刷方案

推荐组合：

- 不保存原始 IP。
- 使用 HMAC(IP + User-Agent + leader_id + time_window + rotating_salt) 生成短期投票键。
- rotating_salt 每 24 小时或 7 天轮换。
- 原始请求日志尽量关闭或缩短保留。
- 风控事件 7-30 天后删除或进一步匿名化。
- 聚合数据长期保留。
- 对可疑请求使用 Turnstile / hCaptcha。
- 对数据中心 IP、代理、同 ASN 爆发流量降权。
- 国家 / 地区只保留粗粒度 GeoIP。

注意：浏览器指纹容易触及隐私和同意问题，不建议使用强指纹。若必须使用，也应只用于安全目的、短期保留，并在隐私政策中说明。

### 9.6 安全设计

- HTTPS 全站强制。
- HSTS。
- CSP。
- CSRF 防护。
- 管理后台 MFA。
- RBAC 权限。
- 审计日志不可被普通管理员删除。
- 数据库每日备份。
- 敏感配置放 Secret Manager。
- 后台导出需要审批。
- WAF 规则保护投票接口。
- 速率限制：IP、ASN、国家、人物、全局多级限流。

## 10. 合规设计

### 10.1 隐私原则

投票支持 / 不支持政治人物可能被解读为个人政治倾向，哪怕系统不要求登录，也应按高敏感度处理。

原则：

- 数据最小化。
- 默认匿名或强假名化。
- 不出售个人数据。
- 不做个体画像。
- 不做跨站追踪。
- 不把投票行为用于政治广告定向。
- 投票事件短期保留，聚合数据长期保留。
- 隐私政策写清楚处理目的、数据类型、保留期限、用户权利。

### 10.2 Cookie 与追踪

建议分层：

1. 必要 Cookie / 本地存储  
   用于安全、投票状态、语言，不做广告追踪。

2. 分析 Cookie  
   默认关闭或经同意后启用。优先使用无 Cookie 的隐私友好分析。

3. 广告 Cookie  
   若使用个性化广告，需要明确同意和退出机制。更推荐只做上下文广告。

### 10.3 地区合规重点

欧盟 / 英国：

- GDPR 下要有合法处理依据。
- 涉及政治观点的个人数据属于高敏感类别，应尽量避免处理可识别个人。
- 非必要 Cookie 通常需要同意。
- 需要提供访问、删除、反对、撤回同意等机制。

美国 / 加州：

- 若达到 CCPA/CPRA 适用门槛，需要提供隐私政策、知情、删除、更正、选择退出销售 / 共享等权利。
- 避免“出售或共享”个人信息，尤其避免跨站行为广告。

中国大陆：

- 若面向中国用户处理个人信息，需关注《个人信息保护法》。
- 若服务器在中国大陆，需评估 ICP 备案。
- 若内容构成互联网新闻信息服务，需评估是否需要许可。
- 政治公共议题内容需要更严格的内容合规和审核流程。

儿童隐私：

- 产品不应设计成儿童产品。
- 不收集儿童个人信息。
- 美国 COPPA 对面向 13 岁以下儿童或明知收集儿童信息的网站有要求。
- 欧盟儿童同意年龄由成员国在 13-16 岁之间确定。

### 10.4 内容合规

简介原则：

- 事实优先。
- 来源可追溯。
- 避免仇恨、煽动、侮辱、暴力鼓励。
- 不发布未经证实的健康、死亡、犯罪、选举资格等声明。
- 对当前选举相关人物，避免发布可能误导选民参与流程的信息。

平台声明：

- 本站不代表任何政府、政党、候选人或国际组织。
- 本站结果不是正式民调。
- 本站不提供投票建议。
- 本站不允许购买投票、刷票或操纵排名。

### 10.5 商业化合规

- 原生广告和赞助必须明显标注。
- 不允许赞助内容伪装成普通人物简介。
- 不接政治竞选广告。
- 不接“提高某领导人支持率”的服务。
- 不把投票者数据卖给政治组织、广告主或数据经纪商。
- API 只提供聚合数据，且最低样本量过滤。

## 11. 云服务器部署方案

### 11.1 MVP 部署

适合启动阶段：

- Cloudflare DNS + CDN + WAF
- Vercel / Fly.io 部署前端和 API
- Neon / Supabase / RDS PostgreSQL
- Upstash / Redis Cloud
- S3 / R2 存储图片
- Sentry 监控

优点：

- 快速上线。
- 运维少。
- 成本低。
- 全球 CDN 体验好。

### 11.2 成长期部署

当日投票量超过 100 万：

- API 拆分为独立 Vote Service。
- 投票写入队列。
- 聚合异步更新。
- 排名缓存到 Redis。
- 分析数据写入 ClickHouse。
- 地图数据预计算。

### 11.3 大规模部署

当全球多区域访问明显增加：

- 多区域边缘部署。
- 数据库主从或区域分片。
- 反作弊服务独立扩展。
- 对热点人物单独缓存。
- 静态页面 ISR / CDN 缓存。
- 排行榜每 1-5 分钟刷新，不必每票实时全站重算。

### 11.4 中国大陆访问选择

两种路线：

1. 海外部署，全球访问  
   成本和合规简单一些，但中国大陆访问速度和可达性不稳定。

2. 中国大陆服务器  
   需要 ICP 备案；若内容被认定为新闻信息服务或涉及特殊许可范围，需要进一步评估。这个路线必须先做法律和内容合规审查。

## 12. 商业化与变现

### 12.1 合规优先的收入模式

1. 上下文广告  
   展示与历史、教育、图书、纪录片、国际关系课程相关的广告。不要基于用户政治倾向定向。

2. 会员订阅  
   面向普通用户提供：
   - 无广告
   - 高级筛选
   - 更多历史趋势
   - 收藏人物
   - 自定义榜单

3. 专业数据订阅  
   面向媒体、研究者、大学、智库：
   - 聚合趋势数据
   - API
   - 国家 / 时间窗口统计
   - 异常过滤说明
   - CSV 导出

4. 数据报告  
   每月发布《全球领导人匿名支持率观察》。免费摘要 + 付费完整版。

5. 嵌入式组件  
   给媒体和教育网站提供可嵌入的“人物支持率组件”。只展示聚合数据。

6. 赞助专题  
   例如“20 世纪领导人历史专题”“诺贝尔和平奖人物专题”。必须明显标注赞助，不影响投票排序。

7. 教育授权  
   给学校、课程平台、历史教育产品提供无广告版本。

8. 捐赠  
   以“支持独立公共数据项目”为定位。捐赠者不能影响排名。

### 12.2 不应做的变现

- 付费投票。
- 付费提高支持率。
- 付费隐藏不支持票。
- 出售用户级投票记录。
- 为政党、候选人、政府机构做定向政治广告。
- 根据某人投票记录推断其政治观点并出售。
- 接受“攻击某人物”的赞助活动。

### 12.3 商业化阶段

MVP：

- 无广告或少量上下文广告。
- 捐赠。
- 先积累公信力。

增长期：

- 会员订阅。
- 媒体嵌入组件。
- 月度报告。

成熟期：

- 聚合数据 API。
- 教育授权。
- 专业机构订阅。

## 18. 关键决策建议

我建议这样定产品：

1. 以“匿名公共情绪数据平台”定位，不做政治宣传平台。
2. 第一版只做网页，不做 App。
3. 不做账号体系，先保持真正低摩擦匿名。
4. 不开放评论，极大降低内容风险。
5. 投票数据按聚合展示，不做个人画像。
6. 简介必须人工审核，AI 只能辅助。
7. 变现先用上下文广告、会员、聚合数据报告，不碰付费投票和政治广告。
8. 上线前先做英文 + 中文，后续扩展多语言。
9. 首批人物少而准，宁可 200 个高质量人物，不要 2 万个低质量人物。
10. 方法论必须公开，这是公信力核心。
